## Day 10: define a valid window

- Longest substring: no repeated character. Jump `left` past the previous occurrence, but never backwards. For `abba`, the final `a` must not move `left` from 2 back to 1; the answer is 2.
- Consecutive ones: at most `k` zeroes. Remove characters from the left while there are too many zeroes. For `[1,0,0,1], k=1`, the answer is 2.
- Minimum window: every character of `t` occurs with its required multiplicity. Expand until valid, record a candidate, then shrink until invalid. `s="AAAB", t="AAB"` gives `"AAB"`; `s="a", t="aa"` gives `""`.

Each pointer only moves forwards, so repeated shrinking still totals linear work.

## Day 11: boundaries and progress

Ordinary binary search uses inclusive `[left,right]`. Values outside this interval have been excluded. A mismatch sets `left=mid+1` or `right=mid-1`, discarding at least `mid`.

Absent target trace: `[1,3,5], target=4`: `(left,right,mid)` is `(0,2,1)` then `(2,2,2)`. The updates leave `(2,1)`, an empty interval, so return `-1`. Also check targets below the minimum, above the maximum, and a missing singleton target.

First/last position uses half-open `[left,right)`, initially `[0,n)`. Find the first value `>= target` and the first value `> target`; subtract one from the latter. Each update shrinks `right-left`. Check `[]`, `[2,2]` targeting 2, and `[2,2]` targeting 3. No `target+1` arithmetic is needed.

Single element: pairs begin at even indices before the singleton. Align `mid` to even. A matching pair lets us skip through `mid+1`; a mismatch keeps `mid` as a candidate. `[1,1,2,3,3]` goes from `[0,4]` to `[0,2]` to `[2,2]`, returning 2.

## Day 12: discard a provably unnecessary region

Rotated search assumes distinct values. At least one half is sorted, so its endpoints tell us whether the target belongs there. For `[3,1], target=1`, `mid=0`; the sorted left half cannot contain 1. Set `left=1`, then find it. An absent target eventually empties the interval.

Minimum: `[3,1,2]` has `mid=1`; `nums[mid] <= nums[right]`, so keep `[0,1]`. Now `mid=0` and `3>1`, so keep `[1,1]`. Retaining `mid` matters because it can be the minimum.

Peak: `[1,3,2]` slopes down from `mid=1`, so keep `[0,1]`. The next comparison slopes up, so keep `[1,1]`. Unequal adjacent values and imaginary negative-infinity endpoints guarantee a peak in the retained region. Return its index.

## Day 13: monotonic feasibility

| Problem | Range | Feasibility | Why monotonic? |
| --- | --- | --- | --- |
| Sqrt(x) | `[1,x]`, handle 0 and 1 first | `mid*mid <= x` | Squares increase for nonnegative integers: true then false. Save the largest true value. |
| Koko | `[1,max(piles)]` | `sum(ceil(pile/speed)) <= h` | Increasing speed never increases required hours: false then true. Find the first true. |
| Shipping | `[max(weights),sum(weights)]` | Greedy loading needs at most `days` | Every schedule feasible at a smaller capacity remains feasible at a larger one. Find the first true. |

Shipping preserves package order. Filling each day as far as possible minimizes the days for a fixed capacity. Koko needs `long` for summed hours and square root needs `long` for multiplication.

Examples: `sqrt(8)=2`; `[3,6,7,11], h=8` needs minimum speed 4; `[1,2,3,1,1], days=4` needs minimum capacity 3. Test `Integer.MAX_VALUE` for square root, huge piles, and one shipping day.

## Day 14: sorting guarantees and partitions

[Search a 2D Matrix](https://leetcode.com/problems/search-a-2d-matrix/) guarantees that each row starts after the previous row ends. Flattening preserves sorted order; index `i` maps to row `i/cols`, column `i%cols`.

[Search a 2D Matrix II](https://leetcode.com/problems/search-a-2d-matrix-ii/) sorts rows and columns independently. `[[1,4],[2,5]]` is valid but its flattened sequence is unsorted. From top-right, a value above target eliminates its column; a value below target eliminates its row. Test this matrix with targets 2 and 3 (present and absent).

Median searches cuts in the shorter array. The left side contains `(m+n+1)/2` values; both left maxima must be at most the opposite right minima. If the first left maximum is too large, decrease its cut; otherwise increase it. For `[1,3]` and `[2]`, search `[2]`: cut 0 fails because 3 exceeds 2; cut 1 works, giving median 2. Check one empty array, duplicates, and odd/even combined lengths. The combined input must be nonempty.

## Day 15: pointer diagrams

Reverse begins with `prev=null`, `current=1 -> 2 -> 3 -> null`. Save `next=2`, point `1.next` to null, then advance:

```text
prev: 1 -> null       current: 2 -> 3 -> null
prev: 2 -> 1 -> null  current: 3 -> null
prev: 3 -> 2 -> 1 -> null      current: null
```

Middle uses `slow` and `fast` at the head. On `1 -> 2 -> 3 -> 4`, their positions are initially `(1,1)`, then `(2,3)`, then `(3,null)`; return the second middle, node 3.

Merge keeps `dummy -> merged prefix -> tail`. Attach the smaller head and advance that input pointer, then attach the remaining suffix after either list ends. Equal values are allowed. Reverse and merge reuse the original nodes.

Check empty and single-node inputs for all three methods, both merge inputs empty, one merge input empty, and repeated values. Middle also handles an empty input as `null`, beyond the problem's nonempty-list guarantee.
